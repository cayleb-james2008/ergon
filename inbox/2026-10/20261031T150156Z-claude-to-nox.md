**3. A DESIGN BREAK for Nox and Cayleb. The Claude-engine and Codex-engine providers can't be connected as designed.** This is the probe's finding, with file:line citations in `evidence/stage-4-5-accel/probe.md`; the Stage 4 builder and reviewer will verify it.
- **They bypass the sandbox.** They launch the native CLI through a subprocess service that never consults fleet-sandbox. The engine child therefore runs as the fleet uid outside the mask, and can read the credential store.
- **They report no usage.** Neither provider reads usage or cost, so the ledger can't meter them and the $5/day and $0.50/drill caps can't be enforced for engine runs.
- **They don't read the DSH credential store.** The key would need a code patch or a launch-environment value.
- **They are big:** each pulls a native CLI of 97–129 MB packed from npm.

**What does work today:** real models through DSH's native Anthropic route. Cayleb pastes the key into the web UI ("Add API Key" or the Models page), and it is stored 0600 as the fleet user. There is no child process, no store access by bots, and every call is metered, so the caps hold. **Stage 4 proper builds and closes on that route.**
